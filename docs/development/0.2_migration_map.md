# OpenPFC 0.1 → 0.2 migration map

**Live document.** Every milestone (M1–M12) that adds, merges, or deletes a
public concept updates this table. It is the single index of what replaces what
and when the old thing is removed. Seeded from the architecture audit §14
(`OPENPFC_ARCHITECTURE_AUDIT.md`) and the execution plan
(`OPENPFC_REFACTORING_EXECUTION_PLAN.md`).

Status legend: **planned** · **in progress** · **done**.

## Field types and allocation

Use `pfc::data::Field<T, MemorySpace>` for grid-allocated fields. Construct with shape and stride parameters or use factory functions like `field_from_subdomain` to create subdomain views.

```cpp
#include <openpfc/kernel/field/field_factory.hpp>
#include <openpfc/kernel/data/grid_field.hpp>
#include <openpfc/kernel/decomposition/decomposition.hpp>

using namespace pfc;

// Factory function for subdomain views (recommended)
auto domain = domain::create({128, 128, 128});
auto decomp = decomposition::create(domain, 4); // 4 subdomains

// Allocate a field for rank 0's subdomain with halo width 1
pfc::data::Field<double, HostSpace> field =
    pfc::data::field_from_subdomain<double>(decomp, 0, 1);

// Direct construction with domain, owned box, and halo
pfc::Box3i owned_box = decomposition::local_box(decomp, 0);
pfc::data::Field<double, HostSpace> field2(domain, owned_box, 1);
```

The `pfc::data::Field<T, MemorySpace>` type supports both unpadded and halo-padded layouts through its halo width parameter. Use `halo_width=0` for tight storage matching the legacy `LocalField` pattern, or `halo_width=n` for padded storage supporting halo exchange in MPI decomposition. The single type unifies these patterns, avoiding the complexity of separate container types.

## Performance optimization

For cache-local layouts, use `pfc::data::Field` with appropriate stride parameters. The `field_from_subdomain` factory creates subdomain views with contiguously strided storage, ensuring optimal memory access patterns for local compute regions.

```cpp
#include <openpfc/kernel/field/field_factory.hpp>
#include <openpfc/kernel/decomposition/decomposition.hpp>

using namespace pfc;

// Create a subdomain view for cache-local compute
auto domain = domain::create({64, 64, 64});
auto decomp = decomposition::create(domain, 4);
int rank = 0;
int halo_width = 1;

auto local_field = pfc::data::field_from_subdomain<double>(decomp, rank, halo_width);

// Access is contiguous within the owned region boundaries
auto size = local_field.local_size();  // returns Int3 of local owned extents
for (int k = 0; k < size[2]; ++k) {
    for (int j = 0; j < size[1]; ++j) {
        for (int i = 0; i < size[0]; ++i) {
            local_field(i, j, k) = compute_value(i, j, k);
        }
    }
}
```

The field's x-fastest row-major layout provides contiguous storage where halo cells are addressable in `[-halo, n + halo)` on each axis. Storage is a single contiguous `(nx + 2*halo) * (ny + 2*halo) * (nz + 2*halo)` buffer, providing optimal cache locality for stencil computations.

## Discrete lattice indexing

Discrete lattice indexing uses `Field`'s coordinate-based `operator(int i, int j, int k)` for direct access, or the `idx()` method for linear indexing when needed for performance or integration with external libraries.

```cpp
#include <openpfc/kernel/data/grid_field.hpp>

using namespace pfc::data;

// Access lattice sites using coordinate-based indexing (recommended)
for (int k = 0; k < field.local_size()[2]; ++k) {
    for (int j = 0; j < field.local_size()[1]; ++j) {
        for (int i = 0; i < field.local_size()[0]; ++i) {
            field(i, j, k) = compute_value(i, j, k);
        }
    }
}

// Linear indexing is available via field.idx() when needed
for (int k = 0; k < field.local_size()[2]; ++k) {
    for (int j = 0; j < field.local_size()[1]; ++j) {
        for (int i = 0; i < field.local_size()[0]; ++i) {
            std::size_t linear = field.idx(i, j, k);
            field.data()[linear] = compute_value(i, j, k);
        }
    }
}

// Physical coordinate queries
pfc::Real3 coords = field.coords(i, j, k);         // physical coordinates
pfc::Int3 global_idx = field.global(i, j, k);      // global lattice indices
```

The field provides both coordinate-based access `operator(i, j, k)` and linear indexing through `idx()`. Global-to-local coordinate translation is built-in via `global()` and physical coordinate queries are available through `coords()`.

## Deprecated APIs

### Legacy field types (prior to 0.2)

The following types are retained for backward compatibility but should not be used in new code:

- **`LocalField<T>` (removed)** — Use `pfc::data::Field<T, MemorySpace>` with `halo_width=0`. The `field_from_subdomain_unpadded()` factory provides the closest migration path.
- **`PaddedBrick<T>` (removed)** — Use `pfc::data::Field<T, MemorySpace>` with `halo_width=n`. Use `pfc::data::field_from_subdomain<T>(decomp, rank, halo)` for the equivalent layout.
- **`DiscreteField<T>` (removed)** — Use `pfc::data::Field<T, MemorySpace>` with stride-aware indexing and the built-in coordinate queries instead.
- **`Array<T>` (removed)** — Replaced by `pfc::data::Field<T, MemorySpace>` for grid-allocated data.

Migrate existing code to `pfc::data::Field` and use the `field_from_subdomain*` factory functions for MPI-domain-aware subdomain views. See the updated sections above for replacement patterns.
